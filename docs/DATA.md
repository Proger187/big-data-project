## ACS PUMS 2019 и 2022 — файлы по людям (person files)

### Источник
- **American Community Survey (ACS), 1-year PUMS**, U.S. Census Bureau. Выборка ≈1% населения США за год.
- Скачаны: **2019** (`data/csv_pus/`) и **2022** (`data/csv_pus (1)/`). Только файлы по людям (`psam_pus*`). Файлов по жилью (`psam_hus*`) нет.
- Условия: данные публичные, распространять можно. В репозиторий не кладём из-за размера: файлы больше 1 GB, а GitHub не принимает файлы больше 100 MB.
- Документация: README в каждой папке. Для расшифровки кодов нужен **PUMS Data Dictionary** за каждый год — его надо скачать отдельно (census.gov → ACS → Microdata → Documentation).

### Файлы

| Файл | Строк 2019 | Строк 2022 | Что внутри |
|---|---|---|---|
| `psam_pusa.csv` | 1 658 808 | 1 724 154 | люди из штатов с кодами `ST` 01–28 (Alabama … Mississippi) |
| `psam_pusb.csv` | 1 580 745 | 1 649 224 | люди из штатов с кодами `ST` 29–56 (Missouri … Wyoming) |
| **Всего** | **3 239 553** | **3 373 378** | 50 штатов + DC |

- 288 колонок в 2019, 287 в 2022. Отличие одно: `MLPI` и `MLPK` (периоды военной службы) в 2022 объединены в `MLPIK`. Остальные колонки совпадают.
- Одна строка = один человек.

### 2016 (для бенчмарка) — отличия формата

- Файлы `ss16pusa.csv` / `ss16pusb.csv` (а не `psam_pus*`), 3 156 487 строк, 284 колонки.
- `SERIALNO` — число без года (`000000064`), читаем как текст.
- Нет колонок `REGION` и `DIVISION` → регион считаем по штату `ST`.
- Способ добраться до работы — `JWTR` (а не `JWTRNS`), код 11 = работал из дома.
- `ADJINC` = 1 007 588 (2019: 1 010 145, 2022: 1 042 311) — по нему скрипт проверяет, что годы не перепутаны.

### Связь

- **`a` и `b` просто склеиваются друг под другом** (одинаковые колонки, штаты не пересекаются) → весь США за год.
- **2019 и 2022 — разные люди.** Это две независимые выборки, связать человека между годами нельзя. Склеиваем по строкам и добавляем колонку `year`.
- **Ключ человека** = `SERIALNO` + `SPORDER` (дублей нет).
  - `SERIALNO` — домохозяйство: люди с одинаковым `SERIALNO` живут вместе. Номер начинается с года (`2022HU…` — обычное жильё, `2022GQ…` — group quarters: общежития, тюрьмы, дома престарелых). В среднем ≈2.4 человека на домохозяйство.
  - `SPORDER` — номер человека внутри домохозяйства.
- Если понадобятся данные по жилью (доход домохозяйства, аренда, интернет и т.п.) — скачать `psam_hus*` того же года и склеить по `SERIALNO`.

### Группы колонок

| Группа | Колонки | Что это |
|---|---|---|
| ID и география | `SERIALNO`, `SPORDER`, `REGION`, `DIVISION`, `ST`, `PUMA` | регион, штат, PUMA (район ≈100 тыс. жителей) |
| Вес | `PWGTP` | сколько людей в населении представляет эта строка |
| Репликационные веса | `PWGTP1` … `PWGTP80` | только для стандартных ошибок по методике Census. Для моделей не нужны |
| Ответы и производные | `AGEP`, `SEX`, `SCHL`, `ESR`, `COW`, `WAGP`, `PINCP`, `WKHP`, `JWTRNS`, `OCCP`, `INDP`, `RAC1P`, `HISP`, `POVPIP`, … (~120 колонок) | демография, образование, работа, доход, дорога на работу, страховка, инвалидность и т.д. |
| Флаги импутации | `F…P` (`FWAGP`, `FAGEP`, … ~100 колонок) | 1 = значение не ответили, а Census досчитал (импутировал) |

### Подвохи

- **Пустое значение ≠ пропуск.** Обычно это «не применимо»: например, `JWTRNS` (как добирался до работы) заполнен только у тех, кто работал на прошлой неделе (~54% строк пустые), `WKHP` — только у работавших за последние 12 месяцев. Настоящие неответы Census уже заполнил (см. флаги `F…P`).
- **Доходы в разных долларах.** `ADJINC` (2019: 1.010145, 2022: 1.042311 — делить на 1 000 000) приводит доходы к долларам *своего* года. Для сравнения 2019 и 2022 нужно ещё поправить на инфляцию между годами (CPI).
- **Top-coding.** Очень высокие доходы заменены на пороговое значение, разное по штатам.
- **PUMA несравнимы между годами.** В 2022 используются новые границы (2020 года): 2 462 PUMA против 2 351 в 2019. Между годами сравнивать на уровне штата или переводить через crosswalk.
- **Коды надо расшифровывать** по Data Dictionary (например, `ESR` 1/2/4/5 = работает, 3 = безработный, 6 = вне рабочей силы. `JWTRNS` 11 = работал из дома).
- **Размер.** Все 288 колонок сразу в pandas — несколько GB памяти. Читать только нужные колонки (`usecols`) и задавать типы. 23 колонки × 1.7 млн строк ≈ 260 MB, один файл читается за ~25 секунд.
- **Названия папок** `csv_pus` и `csv_pus (1)` легко перепутать — см. `docs/IDEAS.md`.

| Домохозяйства (+ group quarters) | 1.43 млн | 1.51 млн | — |

| Работают, 18–64 | 1.39 млн | 1.42 млн | 2.8 млн |
| … из них зарплата > 0 | 1.32 млн | 1.35 млн | 2.7 млн |

Сумма весов `PWGTP` ≈ 328 млн (2019) и ≈ 333 млн (2022) — это население США, то есть веса работают.

### Что учесть в модели

- **Выборка огромная.** LOOCV на миллионах строк нереален, KNN будет очень медленным. Для них — случайная подвыборка (с фиксированным seed) или k-fold CV.
- **Веса.** Для описательной статистики «по США» нужен `PWGTP`. Для предсказательных моделей обычно работают без весов — это решение надо обосновать в отчёте.
- **Импутированные значения.** Решить, оставлять ли строки с флагами импутации в ключевых переменных (например, `FWAGP` = 1 для зарплаты).
