# Правила работы с репозиторием

Цель: в репозитории всегда актуальная версия проекта, и каждый в команде видит, что сделано и что решено.

## Что пушим

| Папка / файл | Что там |
|---|---|
| `code/` | скрипты анализа |
| `outputs/` | небольшие результаты: таблицы (`.csv`), графики (`.png`) |
| `report/` | черновик отчёта |
| `slides/` | презентация |
| `docs/` | документы команды: отчёт о работе, идеи и решения, лог ИИ, описание данных, эти правила |
| `CLAUDE.md`, `AGENTS.md`, `README.md` | инструкции и описание проекта |

## Что НЕ пушим

- **`data/`** — сырые данные. Условия Всемирного банка запрещают их распространять. Каждый скачивает данные сам (инструкция в `README.md`).
- Файлы курса: `Instructions for Project.docx`, `Groups ECON 434.xlsx`.
- Временные файлы: `~$*`, `.RData`, `.Rhistory`, `__pycache__/`, `.venv/`, настройки IDE.
- Пароли, токены, личные данные.
- Файлы больше 50 MB.

Почти всё это уже закрыто в `.gitignore`. Не удаляй оттуда строки без согласования с командой.

## Как работать

1. **Перед началом работы:** `git pull`.
2. **Во время работы:** небольшие коммиты, один коммит = одно осмысленное изменение.
3. **Перед пушем:** `git pull --rebase`, проверить, что код запускается и чужие скрипты не сломаны.
4. `git push`.

**Ветки.** Пока все работают в `main`, нас трое. Если изменение большое или рискованное (переделка чистки данных, смена модели, крупная правка отчёта) — делаем отдельную ветку `имя/что-делаю` и Pull Request, чтобы остальные посмотрели перед слиянием.

**Запрещено:** `git push --force` в `main`, удалять или переписывать чужую работу без согласования.

## Сообщения коммитов

Формат: `[область] что сделано`.
Области: `data`, `code`, `model`, `report`, `slides`, `docs`.

Примеры:
- `[code] загрузка и склейка таблиц Нигерии`
- `[model] logit vs LDA, 10-fold CV`
- `[docs] решение: используем только Нигерию`

## Условия для пуша (чек-лист)

- [ ] Изменение не противоречит принятым решениям (✅) в `docs/IDEAS.md`. Если противоречит — сначала обсуждаем с командой и обновляем решение.
- [ ] Для значимого изменения (новый скрипт, новый результат, изменение плана) есть запись в `docs/WORKLOG.md`. Для опечаток не нужно.
- [ ] Если помогал ИИ — есть запись в `docs/AI_USAGE.md`.
- [ ] Код запускается и не ломает чужие скрипты.
- [ ] В коммите нет данных и временных файлов.

## Правила для ИИ

- ИИ пушит **только по просьбе участника** и только то, что относится к задаче.
- В сообщении коммита от ИИ в конце есть строки:
  - `Requested-by: <имя участника>`
  - `Co-Authored-By: <название ИИ>`
- Правила (`CLAUDE.md`, `docs/GIT_RULES.md`) и статусы ✅/❌ в `docs/IDEAS.md` ИИ меняет только по прямой просьбе и после согласования командой.
