Если ИИ работает в чате без доступа к репозиторию, участник вставляет в начало разговора этот файл и нужные файлы из `docs/`.

## 1. Порядок работы (обязательно, по шагам)

1. **Сначала прочитай**, до любых действий:
   1. этот файл — `CLAUDE.md`;
   2. `docs/GIT_RULES.md` — что и как пушить;
   3. `docs/IDEAS.md` — идеи и принятые решения;
   4. `docs/WORKLOG.md` — минимум последние 3 записи, чтобы знать, где проект сейчас;
   5. `docs/DATA.md` — если задача касается данных или кода.
   Если есть доступ к git — сначала `git pull`, работай с актуальной версией.
2. **Сверь задачу с решениями** в `docs/IDEAS.md`. Если задача противоречит принятому решению (✅) или меняет его — остановись, объясни человеку, в чём противоречие, и не делай, пока команда не обновит решение.
3. **Если задача неясна** — задай один уточняющий вопрос. В мелочах выбери разумный вариант и скажи, какой.
4. **Делай только то, что просили.** Не трогай файлы и куски работы вне задачи, не переписывай чужую работу.
5. **После задачи обнови документы:**
   - `docs/WORKLOG.md` — запись о сделанном (для значимых изменений);
   - `docs/AI_USAGE.md` — что именно сделал ИИ (всегда);
   - `docs/IDEAS.md` — если появилась новая идея или вопрос (статус 💡 «Предложено»; ставить ✅/❌ ИИ сам не может).
6. **Коммит и пуш** — только если человек попросил, по правилам `docs/GIT_RULES.md`.
7. **Отчитайся человеку коротко:** что сделано, какие файлы изменены, что осталось или что нужно решить команде.

## 2. Академическая честность — главное ограничение

- Инструкции к проекту: *"An AI generated project will be considered as plagiarism."*
- Силлабус: любой вклад ИИ должен быть указан **каждый раз**.
- Поэтому ИИ — помощник, а не автор.
  - **Можно:** объяснять методы и код, разбирать структуру данных, искать ошибки, ревьюить, предлагать варианты, помогать с git и организацией, проверять расчёты.
  - **Нельзя** (без прямой просьбы и пометки в `AI_USAGE.md`): писать за команду текст отчёта и слайдов, формулировать исследовательский вопрос и выводы, выдавать готовые результаты, которые никто в команде не понимает.
  - **Код:** ИИ может помогать, но код должен быть простым и понятным, потому что преподаватель может попросить любого участника объяснить любую строку. Объясняй, что и зачем написал.
- Любой вклад ИИ записывается в `docs/AI_USAGE.md`. Без исключений.

## 3. Правила для кода и анализа

- **Язык** — см. `docs/IDEAS.md` (пока не решено: Python или R).
- **Структура:** код в `code/`, скрипты пронумерованы по шагам (`01_load`, `02_clean`, `03_eda`, `04_models`, `05_results`). Маленькие функции, простой код, комментарии по делу. Ключевые расчёты пишем понятно, без «магических» однострочников.
- **Методы — только из курса:** linear regression, logistic regression, LDA, KNN, validation set / LOOCV / k-fold CV, ridge и lasso, polynomial / step functions / splines, decision trees и random forests, PCA, clustering, sentiment analysis. Выбор модели всегда обосновываем — это главный критерий оценки.
- **Воспроизводимость:** фиксированный seed (Python `42`, R `set.seed(1)`), только относительные пути (`data/...`), результаты сохраняются в `outputs/`. Скрипты должны запускаться с нуля по порядку.
- **Данные:** сырые файлы не меняем, вся чистка — в коде. Данные не коммитим (см. `docs/GIT_RULES.md`).
- **Не выдумывай цифры.** Любое число в отчёте или на слайдах должно получаться кодом из репозитория.
